## What did run

* **Same models.** Both checkpoints copied from macM1 and checked:
  dense `3c0891fb...afd7`, spiking `e9a3c929...a074`, test split
  `ad59a2f1...fd2d`, val split `bc703894...257a` (full hashes in the
  prereg and `isoquality.json`).
* **Same framework.** MLX 0.31.1 with `mlx-cuda-12==0.31.1` from the
  pinned N10-C venv (read-only), Python 3.10.18, no new dependency;
  NVML through `ctypes` on `libnvidia-ml.so.1` (driver 595.84).
* **Precision.** MLX's CUDA backend runs fp32 matmuls in TF32 by default
  (relative error 3e-4 vs 4e-7 on a 512x1536x384 product);
  `MLX_ENABLE_TF32=0` is set for every GPU run, as preregistered.
* **Iso-quality reproduced on the GPU** (prereg section 3, 512 fixed
  windows, fp32):

  | | macM1 test | RTX 4090 test | macM1 val | RTX 4090 val |
  |---|---|---|---|---|
  | dense step 12 000 | 3.637163 | 3.637163 | 3.588420 | 3.588420 |
  | spiking step 12 000 | 3.644508 | 3.644492 | 3.588178 | 3.588131 |

  Largest deviation 4.7e-5 nats (tolerance 0.005); test gap
  spiking - dense = +0.0073 nats (margin 0.02): iso-quality holds.
  Test firing rate 13.78 % (macM1 13.78 %). The CUDA arithmetic matches
  macM1 closely enough for the "same models" premise.
* Smoke test (random weights) and two quick-mode dry runs of
  `measure.py` exercised the pipeline (calibration, pairs, replay,
  pause). The first dry run exposed a wrong NVML process-struct layout
  (garbage PIDs), fixed before the run (24-byte `nvmlProcessInfo_t`,
  plus a `/proc` plausibility check with `nvidia-smi` fallback). Dry-run
  logs stay under `/ai/saisail/nh81-kxkm/dryrun/` and are excluded.

## Background noise (why the guard never passed)

Nothing on KXKM was stopped, killed or reconfigured.

* **16:00-19:24, a crash-looping service.** `kxkm-llama-moe.service`
  (user `kxkm`, systemd user unit; `llama-server` with
  Qwen3.5-35B-A3B Q3_K_XL, port 8000, alias `qwen-32b-awq`) restarted
  every ~5 s. Each start briefly appeared as a GPU compute process and
  raised utilisation to 16-43 % for ~2.5 s of every ~5.5 s cycle
  (30 s trace at 0.5 s, 16:45). Idle probe 16:21-16:22 (60 s, no model
  loaded): mean utilisation 9.9 % (max 42 %), board energy 2707 J =
  45.0 W mean, three short-lived foreign compute PIDs besides ComfyUI.
  Guard readings: 16-21 % at every 10-min check from 16:22 to 18:34
  (one 11 %). By 19:25 the loop had slowed (1 start in 30 s).
* **From 18:50, an N10-C freeze job of another session.**
  `experiments.procgen_multiagent_gtm_comm.harness.pretrain` (seeds 101,
  1 M steps, `/ai/saisail/n10c-freeze/`, about 12.8 GB VRAM, board at
  ~170 W) ran from the N10-C venv; guard readings 39-68 % with a busy
  Python process. Under the replication pause rule, a run would have
  paused for it anyway.
* Resident throughout: ComfyUI (pid 712018, 652 MiB, idle), the gpu-swap
  orchestrator (:18890), Xorg/gnome-shell.
  Board idle power between events: 26-67 W (P5 to P2).
